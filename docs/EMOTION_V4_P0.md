# 心潮 4.0 · P0 情绪层（Draft / 默认关闭）

本 PR **不是整体升级到上游心潮·念 4.0**。只落地一个可审计、默认关闭的独立情绪层，为后续偏爱 / 共情 / 慢变底色 / 小窝展示提供兼容底座。

## 开关与边界

- `EMOTION_V4_ENABLED=false`（默认）时：不产生 `state.emotionV4`，Dashboard 不新增 `emotion` 字段，旧 12 维 / 接口 / ACK 链路行为不变。
- 显式开启后，只有**实际已成功结算**的 `interaction_type` 语义事件会更新 `state.emotionV4`。
- 重复 `event_id` 或已完成的 `interaction_id` 不重复计入；日限额拒绝的事件不计入。
- `mind_presence` / 普通 heartbeat / `settleState` / LMC 召回 / 梦 / 读取 Dashboard 不会生成情绪事件。
- 情绪与现有 `drives` 分开存，**不增加或合并花瓣**，不改变 `crave` / `possess` / `social`、身体点火、心跳和拥抱投递。
- 情绪输入**只认服务端白名单内的语义类型**，忽略客户端传入的自由文本和任意数值。持久化的记录只包含类型、坐标和时间戳，无原文。
- 不产生新主动消息、Murmur、唤醒或 LMC 写入。

## 双层逻辑

- `base`：情绪底子（平静 / 低落 / 烦躁 / 安心 / 雀跃），需要有足够偏离且连续 10 分钟的事件证据才换档。
- `cause`：近期事件起因词，至少有 15 分钟展示窗口；和解/安抚能够取代较低优先级起因，轻微亲昵不会立即掩盖一场冲突。
- `valence` / `arousal`：独立的 0–1 坐标，新的真实事件到来时先按经过时间指数回归静息坐标，再打有界脉冲。纯时间流逝只影响**读取时的无副作用投影**，不会修改存储。
- `marks`：展示最近 24 小时结构化起因记录，同种情绪 2 小时内重复合并；`journal` 最多 48 条结构化记录。标记与当前 `cause` 独立：和解可替换当前起因，但不会删除已有冲突记录；低优先级陪伴即使不盖过当前起因，也会留下标记。
- 人格语义映射：`conflict` →「不安」（沿用原 valence / arousal 增量），`companionship` →「安稳」（沿用原数值）。这些标签只在实际语义事件结算后出现；不能把用户没说话的时段自动解释为陪伴事件。

## 兼容

- 旧 `state.json` 不需要一次性重写；开启后首次有效互动才创建 `emotionV4` 字段。
- Dashboard 的 `schemaVersion=1`、`drives`、`topDrives` 等旧字段保留；只有开启并出现有效情绪时，额外返回 `emotion.label/shown/valence/arousal/cause/marks/journal`。
- 关闭开关即停止更新和投影；已存在的 `emotionV4` 数据仍保留在私有状态文件中，便于回滚，不清除历史。
- 这不是 4.0 正式快照全契约：`stamen`、`mixed`、`days` 与 4.0 新驱力尚未提供，不应告诉下游它们已存在。
- **不要从上游复制整包 `state.json` 或合并 12→11 维**；LMC-5 始终是唯一长期记忆层。

## 验收

`npm test` 应验证：默认关闭、12 维不变、事件结果计算隔离、重试幂等、连续情绪惯性、睡眠与静默结算不改情绪、旧状态兼容、Dashboard 隐私与只读、不泄露聊天原文。
